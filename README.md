# Учебный стенд AI-ассистента

Репозиторий объединяет готовые релизы четырёх компонентов в один комплект для локального запуска.

| Компонент | Репозиторий |
|---|---|
| Frontend | https://github.com/OlgaRhythm/ai-assistent-frontend |
| Backend | https://github.com/OlgaRhythm/Market_AI_assistent_backend |
| ML | https://github.com/Leemoon228/ai-assistant |
| Мок маркетплейса | https://github.com/OlgaRhythm/ai-assistent-marketplace-mock |

## Запуск на Windows

Нужны Docker Desktop с Linux containers и Docker Compose. Исходники компонентов и Python для запуска скачанного комплекта не требуются.

1. Скачайте `stand-linux-amd64.tar.gz` и `SHA256SUMS` из Releases этого репозитория.
2. Сравните SHA256 архива с указанной в `SHA256SUMS` через `Get-FileHash`.
3. Распакуйте архив в отдельную папку и выполните в ней `start.ps1`.

```powershell
tar -xzf stand-linux-amd64.tar.gz
.\start.ps1
```

Скрипт проверяет контрольные суммы компонентов, загружает образы и создаёт локальный `.env` с индивидуальными секретами SSO и Grafana.
Храните этот файл приватно. Настройки существующего `.env` сохраняются при повторном запуске.

Откройте http://localhost:8081 и войдите в тестовый аккаунт `alice` / `alice123`.
Интерфейс ассистента доступен на http://localhost:8080.
LLM использует текущий внешний endpoint проекта. При необходимости адрес можно задать через `OLLAMA_BASE_URL` и `OLLAMA_FALLBACK_URL` в локальном `.env`.

Для запуска существующего мониторинга выполните `start.ps1 -Monitoring`.
Grafana доступна на http://localhost:3001. Учётная запись `admin`, пароль находится в локальном `.env`.
Официальные образы мониторинга скачиваются при первом запуске.

Для остановки выполните `docker compose down`. Не добавляйте `--volumes`, если хотите сохранить данные.
Порты можно переопределить в `.env` через `FRONTEND_PORT`, `BACKEND_PORT`, `ML_PORT`, `MARKETPLACE_PORT`, `GRAFANA_PORT` и `PROMETHEUS_PORT`.

## Выпуск компонентов и стенда

В каждом компоненте тег `v1.2.3` запускает тесты, сканеры и выпуск образа.
Релиз содержит Docker-архив, `manifest.json`, `SHA256SUMS`, состав зависимостей CycloneDX и отчёт Trivy по готовому образу.
Мок дополнительно выпускает существующий образ webhook-receiver.

Логика упаковки компонентов находится в общем CI `.github/workflows/component-release.yml` этого репозитория.
CI каждого приложения вызывает его по закреплённому коммиту и передаёт перечень образов.
Отдельные скрипты упаковки в приложениях не требуются.
Теги всех пяти репозиториев используют формат `vMAJOR.MINOR.PATCH`. Первый общий выпуск — `v0.1.0`.

Тег `v1.2.3` в этом репозитории собирает общий комплект.
Workflow получает последние опубликованные стабильные релизы компонентов и сохраняет их выбор в `resolution.json` черновика релиза.
Повторная попытка использует этот же выбор. Контрольные суммы проверяются до запуска образов.
Для первого выпуска состав четырёх компонентов `v0.1.0` заранее закреплён в `releases/v0.1.0.json`: workflow использует этот файл вместо повторного выбора latest.
После проверки совместного запуска формируется архив стенда и публикуется релиз.
Если у компонента ещё нет релиза общего формата, сборка останавливается с указанием компонента.

`manifest.json` внутри комплекта фиксирует версии, исходные коммиты, идентификаторы образов и суммы файлов.
Отчёты зависимостей хранятся рядом с каждым компонентом в `components/`.
Уязвимости сохраняются для разбора. Текущая политика Trivy — формирование отчёта. Находки Gitleaks блокируют CI компонентов.

Проверка комплекта включает доступность сервисов, SSO, отказ без токена, изоляцию заказов, проксирование frontend, классификацию и один реальный ответ текущей удалённой LLM.
Ollama запускается на внешнем сервере проекта. GitHub Actions использует этот endpoint без локальной загрузки весов.
Если внешний сервер недоступен или не вернул ответ, проверка завершится ошибкой, а релиз останется черновиком.
Локальная команда `python scripts/smoke.py PATH` проверяет запуск без внешней генерации. Флаг `--with-generation` дополнительно проверяет ответ LLM.
Запуск на локальном компьютере выполняет участник команды. Автоматизация заканчивается публикацией учебного комплекта.

## Проверка самого сборщика

```powershell
python -m unittest discover -s tests -v
```

Обновлять компоненты можно независимо. Для общего комплекта сохраняются версии, фактически выбранные при его выпуске.
